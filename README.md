# slack-agent-org

"사람 한 명 + AI 에이전트" 조직에서 에이전트 한 명이 자기 컴퓨터 앞에 앉아 Slack으로 일하게 하는 런타임입니다.
에이전트는 사람과 똑같이 **화면을 보고 마우스·키보드로** Slack에 답합니다. 메시지를 듣는 귀만 Socket Mode입니다.

이 컴퓨터 한 대가 에이전트 한 명의 장비입니다. 새 장비를 에이전트 장비로 만드는 절차는
**[docs/mac-setup.md](docs/mac-setup.md)** 에 있습니다. 에이전트가 이 저장소에서 작업할 때의 고정 전제는
[CLAUDE.md](CLAUDE.md)에 있습니다.

```
           Slack (워크스페이스)
   ┌─────────────┴──────────────┐
   │ Socket Mode (아웃바운드 WS)  │ ← 사람과 같은 방식: 화면에서 클릭·입력
   ▼                            │
 귀 src/slack ──▶ src/inbox ──▶ src/agent (한 번에 한 턴)
 (수신·읽기 전용)  주소 판별·대기열      │ 턴마다 새 엔진, 기억은 런타임이
                    ▲                ▼
                    │         두뇌 src/engine (claude -p)
                    │                │ MCP over localhost (토큰)
                    └── 알림 ──  src/tools ──▶ 손 src/desk ──▶ 화면·마우스·키보드
```

```
src/
├── slack/       # 귀 — Socket Mode 수신(Bun 내장 WebSocket) + 이름 조회(읽기 전용). @slack/*는 여기서만
├── inbox/       # 대기열 — 주소 판별(나에게 온 말인가), 루프 정지 규칙, 알림 문구
├── desk/        # 눈과 손 — 화면 변화·글자 읽기·스크린샷, 클릭·입력 (macOS 드라이버 + 테스트용 memory 드라이버)
├── tools/       # 데스크를 MCP 도구로 제공 (localhost, bearer 토큰). 엔진이 무엇이든 같은 책상
├── engine/      # 두뇌 — 드라이버 계약 + claude-cli 드라이버
├── agent/       # 런타임 루프(협조적 인터럽트) + 프롬프트
├── state/       # 대화별 기억(오간 말·작업 기록), 재시작에도 남는 대기열 (file/memory)
├── ops/         # launchd 서비스 정의
├── validation/  # 스키마 검증 파사드 (현재 zod/mini, 교체 가능)
├── config.ts    # 모든 설정은 여기서 부팅 시 검증
├── container.ts # 컴포지션 루트 — 드라이버 선택, 프로세스당 싱글톤
└── index.ts     # 엔트리포인트 — 부팅 순서, 협조적 종료
native/desk-helper.swift  # CGEvent로 마우스·키보드 이벤트를 보내는 작은 네이티브 도우미
scripts/                  # doctor(장비 점검), service(launchd 설치·재시작·제거)
```

## 요구 사항

| 런타임 | 버전        |
| ------ | ----------- |
| Bun    | **1.4.2**   |
| Node   | **24.19.0** |

버전은 `package.json`의 `packageManager`와 `engines`에만 적혀 있습니다. 그 밖에 macOS(Xcode Command Line Tools —
`swiftc`), 로그인된 Claude Code CLI, Slack 데스크톱 앱(또는 브라우저)이 필요합니다.

## 시작하기

```bash
bun install               # 의존성 + husky 훅
cp .env.example .env      # 값 채우기 — 비밀값은 절대 커밋 금지
bun run desk:build        # 손(네이티브 도우미) 빌드 → .bin/desk-helper
bun run doctor            # 이 장비가 준비됐는지 항목별 점검
bun run start             # 포그라운드 실행 (첫 실행·디버깅)
bun run service:install   # 상시 실행 (launchd)
```

| 명령                        | 설명                                                                    |
| --------------------------- | ----------------------------------------------------------------------- |
| `bun run start`             | 에이전트 실행 (Ctrl+C 한 번: 현재 턴을 마치고 종료, 두 번: 강제 종료)   |
| `bun test`                  | 단위 + 통합 테스트. Slack·화면·Claude 없이 한 번에 실행                 |
| `bun run check`             | prettier + eslint + tsc + knip + test 전체 게이트 (pre-push, CI와 동일) |
| `bun run desk:build`        | `native/desk-helper.swift` 컴파일                                       |
| `bun run doctor`            | 화면·권한·Claude 로그인·Slack 토큰·Socket Mode 점검                     |
| `bun run service:install`   | launchd 에이전트 설치 후 시작 (로그: `data/logs/`)                      |
| `bun run service:restart`   | SIGTERM → 현재 턴을 마치고 종료 → launchd가 다시 시작                   |
| `bun run service:uninstall` | 중지 후 제거                                                            |

## 아키텍처 결정

### 수신과 발신은 다른 길로

- **수신(귀)**: Socket Mode. 아웃바운드 웹소켓만 쓰므로 집 네트워크에 포트를 열지 않습니다. 프로세스에는
  App-Level Token(`xapp-`)과 이름 조회용 읽기 토큰만 들어옵니다. Socket Mode 클라이언트는 Bun 내장 WebSocket으로
  직접 구현했습니다(`src/slack/socket.ts`). `@slack/socket-mode`는 연결 유지 ping에 Node 전용 `undici.ping`을 써서
  Bun에서는 연결이 2초마다 끊깁니다.
- **발신(손)**: GUI. 에이전트는 화면에서 입력창 좌표를 찾아 클릭하고 입력하고 Enter를 누릅니다.
  사람처럼 보이기 위해서가 아니라 "모두가 같은 환경·방식으로 일한다"는 조직 원칙 자체입니다.
- 이 경계는 코드와 토큰 양쪽에서 강제됩니다. ESLint는 `src/slack` 밖에서 Slack SDK를, `src/slack` 안에서는
  발신 네임스페이스(`chat`, `files`, `reactions`, `apiCall` …) 접근을 막습니다. 부팅 시에는 읽기 토큰의 scope를
  확인해 `*:write`가 하나라도 있으면 시작을 거부합니다(`SlackDirectory.assertReadOnly`).

### DM을 받으려면 "사용자 대신 이벤트 구독"

에이전트는 봇이 아니라 정식 멤버 계정입니다. 사람이 에이전트에게 보낸 DM은 사람 ↔ 에이전트 계정 사이의 대화라서
**봇 이벤트(`message.im`)로는 들어오지 않습니다**. 그래서 Slack 앱의 이벤트를 "Subscribe to events on behalf of
users"로 구독하고 앱을 **에이전트 계정이 승인**합니다. 그러면 에이전트 계정이 볼 수 있는 DM·그룹 DM·채널의
메시지가 Socket Mode로 들어오고, 승인 때 받은 사용자 토큰(`xoxp-`, 읽기 scope만)을 이름 조회에 씁니다.
설정 절차는 [docs/mac-setup.md](docs/mac-setup.md) 1단계에 있습니다.

### 주소 판별과 루프 정지 (`src/inbox/addressing.ts`)

Slack(설정 레이어)은 다 보내고, 애플리케이션 레이어가 "나에게 온 말인가"를 정합니다.

- 받는 것: DM과 그룹 DM, 에이전트를 멘션한 채널 메시지, 에이전트가 말한(또는 시작한) 스레드의 답글.
- 엿듣는 것(overheard): 그 밖의 채널 메시지 중 다른 멤버를 멘션하지 않은 것. 아래 채널 판단으로 넘어갑니다.
- 받지 않는 것: 자기 메시지, 봇 메시지, 입퇴장 같은 시스템 메시지, 같은 메시지의 중복 수신, 다른 사람만 멘션한
  채널 메시지.
- **루프 정지**: 한 채널에서 사람이 끼지 않은 채 에이전트가 `MAX_AGENT_EXCHANGES`번 말하면, 사람이 다시 말할
  때까지 그 채널에서는 사람 말에만 답합니다(엿들은 글도 같음). 사람은 `HUMAN_SLACK_USER_IDS`로 구분합니다.

### 채널 판단: 부르지 않아도 답할 글 (`src/agent/triage.ts`)

사람은 멘션을 받을 때만 답하지 않습니다. 채널 알림을 훑어보고 자기가 답할 글이면 끼어듭니다. 채널 판단은 그
훑어보기입니다.

1. 엿들은 글은 채널별로 `TRIAGE_WAIT_SECONDS`(기본 30초) 동안 모읍니다. 연달아 올라온 글은 한 번에 봅니다.
2. 판단 모델(`TRIAGE_MODEL`, 기본 `haiku`)을 도구 없이 한 번 부릅니다(`claude -p`, `--tools ""`, MCP 서버 없음,
   `--max-turns 1`). 입력은 그 채널의 최근 기록과 작업 기록, 판단할 글(작성자가 사람인지 에이전트인지 포함),
   에이전트의 역할(`AGENT_ROLE`)입니다. 출력은 `{"respond", "ids", "reason"}` JSON 한 줄입니다.
3. "답한다"면 그 글이 판단 이유와 함께 대기열에 들어갑니다. 이후는 다른 메시지와 똑같습니다(작업 중이면 🔔 알림,
   쉬고 있으면 턴). 대기열에서는 직접 받은 글(DM·멘션·참여 스레드)이 먼저입니다.
4. "안 답한다"면 이유만 로그(`triage: staying quiet`)에 남깁니다. 답을 읽을 수 없거나 호출이 실패해도 답하지 않습니다.

판단은 턴이 아닙니다. 화면을 쓰지 않으므로 진행 중인 턴과 별개로 돌고, 판단끼리는 한 번에 하나씩입니다.
에이전트에게는 그 글이 "나를 부르지 않은 채널 글"로 보이고, 답하기 전에 최신 대화를 확인해 그사이 다른 사람이
답했으면 넘어가라는 안내가 붙습니다. 끄려면 `CHANNEL_TRIAGE=off`입니다(엿들은 글은 기억에만 남음).

### 협조적 인터럽트 (`src/agent/runtime.ts`, `src/tools/inbox-tools.ts`)

- 턴은 한 번에 하나이고, 밖에서 끊지 않습니다. 작업 중 새 메시지는 대기열에 쌓이고, 에이전트에게는 자기 도구
  결과 끝에 붙는 한 줄 알림(🔔 새 Slack 메시지 N건)으로만 보입니다.
- 에이전트는 멈춰도 안전한 지점에서 직접 고릅니다: `inbox_peek`(보기만), `inbox_take`(이번 턴에 가져와 처리),
  `inbox_yield`(메모를 남기고 일시정지 → 대기 메시지를 먼저 처리한 뒤 그 메모와 함께 재개).
- 턴 사이 순서: 직접 받은 메시지 중 가장 오래 기다린 것의 대화(그 대화에 쌓인 메시지 전부) → 채널 판단으로 들어온
  글의 대화 → 대기 메시지가 없으면 가장 최근에 멈춘 일 → 잠.
- 종료도 같습니다. SIGTERM을 받으면 듣기를 멈추고 현재 턴이 끝나길 기다린 뒤 대기열을 저장하고 나갑니다.
  launchd의 `ExitTimeOut`은 그래서 넉넉합니다(600초).

### 기억은 런타임이, 엔진은 턴마다 새로

채널이나 DM 하나(스레드 포함)가 대화 하나입니다. 엔진은 턴마다 새 세션으로 시작하고(`--resume` 없음),
대화의 기억은 런타임이 텍스트로 보관해 턴 프롬프트 앞에 붙입니다.

- **오간 말**: 귀가 들은 그 대화의 메시지 — 에이전트에게 온 것, 에이전트 자신이 화면으로 보낸 것, 채널의 다른 말까지.
  대화마다 최근 40개를 저장하고, 프롬프트에는 최근 것부터 6천 자까지 넣습니다.
- **작업 기록**: 턴을 마칠 때 엔진이 남긴 마지막 말(한 일, 지금 상태, 남은 일). 대화마다 최근 5개.

예전처럼 세션을 이어 쓰면 지난 턴들의 스크린샷과 조작이 모두 매 호출에 다시 실려, 맥락이 10만 토큰을 넘고
한 시간 넘게 쉰 뒤의 첫 답장이 그 맥락 전체를 캐시에 다시 쓰게 됩니다. 지금은 턴이 몇천 토큰에서 시작합니다.
기억과 대기열은 `data/state.json`(version 2)에 원자적으로 저장됩니다. version 1 파일은 대기열만 옮겨 읽습니다.

엔진은 `ENGINE_WORK_DIR`(기본 `~/.slack-agent-org/engine`)에서 실행됩니다. 이 저장소 안에서 실행하면 개발자용
`CLAUDE.md`가 매 호출에 실리기 때문입니다.

### 엔진은 드라이버

`ENGINE_DRIVER`로 고릅니다. 현재 드라이버는 `claude-cli` 하나입니다: 이 맥에 로그인된 Claude 계정으로
`claude -p`를 실행하므로 프로세스에 API 키가 없습니다. 에이전트가 받는 능력은 데스크 도구뿐입니다
(`--tools ""`로 셸·파일 도구 없음, `--strict-mcp-config`로 다른 MCP 없음, `--permission-mode dontAsk`로 그 밖은 거부).
`--max-turns`는 끝나지 않는 턴을 위한 브레이크입니다.

데스크는 localhost MCP 서버로 제공되므로, 나중에 GPT 에이전트를 붙일 때도 같은 책상(같은 도구, 같은 알림,
같은 인터럽트 규칙)을 씁니다. MCP 서버는 `127.0.0.1`에만 열리고, 부팅 때 만든 토큰이 없으면 401입니다.
토큰은 0600 권한 파일로만 엔진에 전달됩니다.

### 눈: 싼 눈과 비싼 눈 (`src/desk/vision.ts`, `src/tools/describe.ts`)

스크린샷 한 장은 모델 입력으로 약 1천 토큰이라, 확인할 때마다 찍으면 비용 대부분이 화면이 됩니다.
그래서 보는 방법을 비용 순으로 나눕니다. 셋 다 화면 픽셀에서만 나오므로 사람이 볼 수 없는 정보는 없습니다.

| 눈            | 언제                                                                                                           | 비용                                 |
| ------------- | -------------------------------------------------------------------------------------------------------------- | ------------------------------------ |
| 화면 변화     | 모든 조작 도구와 `wait`의 결과에 자동으로 붙음: 마지막으로 본 화면과 비교해 바뀐 영역(최대 4곳)과 그 안의 글자 | 수십~수백 토큰                       |
| `read_screen` | 글자를 찾거나 읽을 때. `region`으로 좁힐 수 있음                                                               | 읽은 글자만큼 (최대 3천 자)          |
| `screenshot`  | 처음 화면을 파악할 때, 글자로 알 수 없을 때(아이콘·그림·배치). `region`으로 일부만 볼 수 있음                  | 전체 약 1천 토큰, 일부는 면적에 비례 |

비교와 글자 읽기는 Swift 도우미가 합니다(`diff`: 12px 블록 단위 비교, `ocr`: Vision 프레임워크, 한국어·영어).
비교 기준은 마지막으로 화면 전체를 본 순간(`data/screen/reference.png`)입니다. 화면의 40% 이상이 바뀌면 새 화면으로 보고
글자를 읽지 않습니다. 비교용 화면에는 마우스 포인터를 넣지 않습니다.

### 좌표계 (`src/desk/geometry.ts`)

모델은 긴 변이 `DESK_MAX_EDGE`(기본 1440px) 이하인 스크린샷을 보고 그 이미지의 픽셀로 답합니다. 드라이버가
이를 화면 포인트로 바꿉니다(레티나는 포인트당 2픽셀). MacBook Air 13"(1440×900pt)는 1:1입니다.

### 환경 설정과 시간

장비를 바꾸거나 다른 에이전트에게 주는 일은 `.env` 교체로 끝납니다. 모든 값은 `src/config.ts`에서 부팅 시
검증됩니다. 프로세스는 UTC로 돌고, 에이전트에게 보여 주는 시각만 `TIME_ZONE`으로 바꿉니다.

## 테스트 전략

- **단위**: 주소 판별과 루프 정지, 대기열(알림 수·take·대화 묶음·대기·스냅샷), Slack 이벤트 파싱과 쓰기 scope
  판별, 키 조합·좌표 변환, 상태 파일(재시작·동시 쓰기·손상 파일 거부), stream-json 파싱과 CLI 인자, launchd plist.
- **Socket Mode**: 가짜 Slack WebSocket 서버로 수신 확인(ack), 메시지 전달, 재연결 요청·연결 끊김 후 재연결, 같은
  토큰을 쓰는 다른 연결 경고, 종료, 토큰 거부.
- **도구 서버**: 실제 MCP 클라이언트로 HTTP 호출 — 도구 목록·스키마, 토큰 없는 요청 401, 손 동작, 잘못된 인자,
  알림 표시와 해제, take/yield.
- **엔진**: 가짜 `claude` 실행 파일로 실제 프로세스 실행 경로(결과 읽기, 실패) 검증. 판단 모델의 인자(도구·MCP 없음)와 답.
- **채널 판단**: 각본 판단 모델로 채널별 모아 보기, 고른 글만 이유와 함께 대기열로, 답 안 함·읽을 수 없는 답·실패 시 침묵,
  대기 시간 후 자동 판단, 종료 시 진행 중 판단 마무리.
- **런타임**: 각본 엔진으로 대화별 기억 주입과 작업 기록 저장, 턴 중 도착한 메시지, 일시정지와 재개 순서, 실패 후 계속, 종료 시 대기열 보존.
- **통합**: 실제 컨테이너 배선에 바깥만 바꿔(memory 귀·책상·상태, 각본 모델) DM 수신 → 화면 조작으로 답장 →
  자기 메시지 무시까지 한 번에 검증합니다. 멘션 없는 채널 질문이 판단을 거쳐 턴이 되는 경로도 검증합니다.
